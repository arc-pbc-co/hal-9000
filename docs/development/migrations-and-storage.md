# Migrations and Object Storage

HAL now has two production-readiness foundations:

- Alembic migrations for database schema changes.
- An object-store abstraction for PDFs, extracted text, and generated artifacts.

## Database Migrations

Alembic is configured in `alembic.ini` and `migrations/env.py`.

The migration environment resolves database URLs in this order:

1. `HAL9000_DATABASE__URL`
2. `DATABASE_URL`
3. `sqlalchemy.url` from `alembic.ini`

Create or upgrade a new database:

```bash
HAL9000_DATABASE__URL=sqlite:///./hal9000.db alembic upgrade head
```

Production database URLs should use the psycopg SQLAlchemy dialect:

```bash
HAL9000_DATABASE__URL=postgresql+psycopg://user:password@host:5432/hal9000 \
  alembic upgrade head
```

For existing local databases that were already created with SQLAlchemy
`create_all`, stamp them instead of replaying the initial create migration:

```bash
HAL9000_DATABASE__URL=sqlite:///./hal9000.db alembic stamp head
```

Generate future migrations from model changes:

```bash
HAL9000_DATABASE__URL=sqlite:///./empty_autogen.db \
  alembic revision --autogenerate -m "describe change"
```

Review autogenerated migrations before committing them.

## Object Storage

Local filesystem storage remains the development default:

```python
from hal9000.storage import create_object_store_from_settings

store = create_object_store_from_settings(settings)
stored = store.put_bytes(
    "outputs/run-report.md",
    b"# Run Report",
    content_type="text/markdown",
)
```

The local backend stores objects under `settings.storage.root_path` and returns
stable `hal-local://...` URIs.

Production storage should use an S3-compatible backend:

```bash
HAL9000_STORAGE__BACKEND=s3
HAL9000_STORAGE__BUCKET=firm-hal-artifacts
HAL9000_STORAGE__PREFIX=hal9000/
HAL9000_STORAGE__REGION=us-east-1
```

For non-AWS S3-compatible services, also set:

```bash
HAL9000_STORAGE__ENDPOINT_URL=https://s3.example.com
```

Credentials are resolved by boto3's normal provider chain: environment
variables, AWS profiles, IAM roles, or workload identity. S3 objects return
stable `s3://bucket/prefix/key` URIs.

## Vector Storage

HAL is pgvector-first for production retrieval while keeping tests and local
development SQLite-compatible. The current vector slice adds:

- `VectorConfig` with `backend=pgvector`, `embedding_provider=fake`,
  `embedding_dimension=1536`, and optional `embedding_model`.
- A deterministic fake embedding provider for tests.
- `chunk_embeddings` records for document chunk vectors.
- A Postgres-only `vector(1536)` column when the migration runs against
  Postgres with pgvector available.

Install production extras as needed:

```bash
pip install -e '.[postgres,s3,vector]'
```

Treat the embedding dimension as a deployment contract. Changing it later needs
a new migration and a re-embedding/versioning plan.
